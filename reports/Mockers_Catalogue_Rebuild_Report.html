The Root Problem

Every issue on the store traced back to one decision: the garment was stored as a variant option, not as a product.

One design was a single Shopify product with three options — Style × Colour × Size — up to 137 variants on one product. Shopify's entire merchandising layer (collections, discounts, inventory, reports, ad feeds) works on products. It cannot see option values.

A 30% discount on the old “Hoodies” collection discounted the t‑shirts too, because each product in it was a whole design, not a hoodie.

What we changed

The catalogue was rebuilt so that one product = one design on one garment, with Colour and Size as the only variants. This is the same model Threadless uses.

Storefront & UI Fixes

Splitting the catalogue exposed several display problems. Each was traced to its cause and fixed in the theme.

Colour swatches showing black FIXED

The theme passed the colour name straight to the browser as a CSS colour. White, Black and Pink happen to be valid, so they worked. Dark Green, Aegean Blue, Burgundy and Beetroot Purple are not valid CSS colours, so the browser discarded them and the swatch stayed black. All 15 colours now have real colour values.

Product page layout FIXED

The page was set to a full‑width layout that stacked the image on top and centred everything underneath. Switched to a two‑column layout: image on the left, title, price, style picker, colour, size and buy button on the right.

Duplicate designs in product grids FIXED

Because one design is now several products, grids repeated the same artwork. Fixed in four places:

  • Browsing pages — new design‑level collections show one card per design
  • Product cards — the design name is the headline, the garment is the line beneath it, so two cards are never identical
  • You May Also Like — no longer recommends other garments of the design you are already viewing
  • Recently Viewed — collapses to one card per design

Garment picker on the product page NEW

A Threadless‑style row showing every garment the design comes on, each with its own price, so a customer can move between them without losing the design. Inside the quick‑view popup it swaps in place instead of throwing the customer out to a new page.

Built natively in the theme — no paid app and no extra monthly cost.

Discount targets — hidden from the storefront

CollectionProductsRule
Winter – All Garments108Hoodies + Sweatshirts
Summer – All Garments167All three tee types
A discount has to reach every garment, but a shopper should never scroll past the same design twice. So the two jobs were split: point discounts at the hidden all‑garment collections, and let menus and the homepage use the season collections. The hidden pair is unpublished from the storefront, so it cannot be browsed by accident — a discount can still target it normally.

Still Outstanding

Two items remain, and both need artwork rather than development.

Product photography PENDING

  • 72 images show the wrong colour. For example, every colour of one t‑shirt design serves the black photo, so a customer choosing White sees a black shirt.
  • 88 colour and garment combinations have no photo at all and fall back to a plain colour block.
Both problems existed in the old catalogue and were carried across unchanged. Every case is listed by design, garment and colour in the accompanying QA file. These need the correct mockup files — no code can resolve them.

Housekeeping PENDING

  • A homepage block still promotes a “Varsity Round Neck Sweatshirt”, which is not one of the five garments sold.
  • Four older homepage content blocks may now be redundant and are worth reviewing together.
  • Colour swatch values are close approximations from the colour names — worth confirming against the real garments.
